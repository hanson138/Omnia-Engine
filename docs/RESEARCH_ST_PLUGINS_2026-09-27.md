## 对 Omnia 的建议（推论，不是上述项目已实现的保证）

1. **保留两条清楚标识的真实 Jev 路径。** 默认“本地服务端直连 TypeSafe/Jev”：浏览器扩展只向 `127.0.0.1` 的桥提交最小认知输入，桥在进程环境持有 API key，直接调用 TypeSafe，完全绕过 Vercel；继续执行 Origin、loopback、超时和输出校验。另提供用户主动启用的“浏览器 BYOK 直连 Vercel Gateway”：由 ST 页面向 Gateway `/v1/evaluate` 发请求，密钥在浏览器内存和网络请求中可见。2026-09-27 的无密钥 CORS 预检发现，TypeSafe 原生 `/v1/systemone` 对本机 ST 来源返回 `Disallowed CORS origin`，而 Gateway `/v1/evaluate` 允许该来源，详见[Jev 直连可行性记录](JEV_DIRECT_API_NOTES_2026-09-27.md)。两者共享相同的 `CharacterCognitionProvider` 输出契约，不能共享密钥存储假设。参考项目确有自定义 API 或浏览器直接请求能力，但其做法不构成 Omnia 的安全论证。[shujuku API](https://github.com/AlbusKen/shujuku/blob/599e3580c3106fa234ead38fdfe8625080419143/src/service/ai/api-call.ts) · [LittleWhiteBox 直连 adapter](https://github.com/RT15548/LittleWhiteBox/blob/a2b39f746e966563b98ffea745cb2fcae46d4bf5/modules/agent-core/adapters/openai-compatible.js)
2. **BYOK 的产品边界应显式。** 默认不持久化浏览器 key；若提供“记住密钥”，单独提示其会进入 ST 用户设置/浏览器可读范围，绝不放进导出文件、诊断日志、错误文字或 URL。测试页仅显示配置状态和掩码，不回显原文。把 host 复用 ST 已配置 provider 与用户自填 BYOK 视为不同选项。参考项目的配置字段中确有 `apiKey`，但无法据此断定安全。[shujuku 预设](https://github.com/AlbusKen/shujuku/blob/599e3580c3106fa234ead38fdfe8625080419143/src/service/settings/api-preset-service.ts) · [LittleWhiteBox provider](https://github.com/RT15548/LittleWhiteBox/blob/a2b39f746e966563b98ffea745cb2fcae46d4bf5/modules/agent-core/provider-config.js) · [Yuzi README 声明](https://github.com/yuzi83/st-yuzi-phone/blob/86ac1b03044637d2ec3e0bb5859301c286195c53/README.md)
3. **设置成熟度优先于面板扩张。** 增加 schema 版本、旧设置迁移、按角色/聊天作用域与来源提示；保存时一次规范化；删除/改名预设时处理悬挂引用。把“测试连接”“运行一次仅诊断不注入”“取消请求”“重试/冷却状态”“最近一次错误类别”做成可操作反馈。参考依据是 [Yuzi 设置校验](https://github.com/yuzi83/st-yuzi-phone/blob/86ac1b03044637d2ec3e0bb5859301c286195c53/modules/settings/schema.js)、[shujuku 预设引用](https://github.com/AlbusKen/shujuku/blob/599e3580c3106fa234ead38fdfe8625080419143/src/service/settings/api-preset-service.ts) 与 [shujuku HTTP 错误分类](https://github.com/AlbusKen/shujuku/blob/599e3580c3106fa234ead38fdfe8625080419143/src/service/ai/api-call.ts)。
4. **导入导出先限制为非秘密配置。** 附带格式版本、来源、校验结果预览和冲突处理；候选认知数据与 API key 不进入配置包。此为 Omnia 新契约，不应直接复制其他插件的任务/表格格式。[LittleWhiteBox 任务 UI](https://github.com/RT15548/LittleWhiteBox/blob/a2b39f746e966563b98ffea745cb2fcae46d4bf5/settings.html) · [shujuku 导入模块](https://github.com/AlbusKen/shujuku/blob/599e3580c3106fa234ead38fdfe8625080419143/src/service/import/import-executor.ts)
5. **发布包必须可独立安装。** `manifest.json` 指向已提交、与源码同版的 bundle；发布检查覆盖 manifest 版本、bundle 存在、设置迁移、provider mock 错误矩阵和 ST 实际加载。Yuzi 的 [README 发布链](https://github.com/yuzi83/st-yuzi-phone/blob/86ac1b03044637d2ec3e0bb5859301c286195c53/README.md) 对这一点尤其明确。

## 建议的最近实施顺序

1. 先抽出 `TypeSafeJevProvider` 共享请求/响应契约，桥端实现直连 TypeSafe 并做无密钥、401、429、5xx、超时、畸形响应和旧 revision 的测试。
2. 加浏览器 Gateway BYOK provider，明确默认仅会话内持钥；用模拟 HTTP 与真实浏览器测试 CORS/重载/模式切换/密钥遮蔽。不得把“本机桥健康”误显示为“Gateway 真实评估成功”。
3. 做设置版本迁移、连接测试、结构化状态/错误、脱敏诊断导出，再补 ST 安装与升级回归。

边界：这份材料是源码比较，不包含真实 Jev/TypeSafe 质量测试，也未审计上述第三方插件。GitHub `main` 随时间变化；实施前应重新核对相关接口。

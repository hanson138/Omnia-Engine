# SillyTavern Jev 扩展冻结记录（2026-09-27）

## 决定与边界

暂停 `sillytavern-extension` 分支上的 Jev 接入和产品化工作，回到 Omnia Engine 连续叙事运行时主线。用户报告 Vercel 上的 Jev API 重新收费且频繁资源枯竭；本记录不把服务可用率或价格当作独立测量结果。冻结是优先级调整，不表示扩展质量、Jev 模型质量或两条直连方案已经验收。

本分支保留 ST 原生 UI 扩展的可安装文件、源码、锁文件、测试、本机实验桥和历史 TavernHelper 实验入口。不会向 `main` 合并，也不会在冻结时追加真实 API 调用。

## 已有内容与证据

- ST 安装需指定本分支；根目录已有 `manifest.json`、`index.js`、`style.css`。本机复制安装及隔离 ST 1.19.0 的加载、`mock + DEBUG` 注入一次、`OFF` 不注入已实测，见 [RESULTS.md](RESULTS.md)。远端分支结构与构建产物此前经浅克隆核对；远端安装界面操作尚未实测。
- 角色候选证据、认知快照、过期结果拒绝和桥接接口已实现。当前 `bridge` 仍依赖相邻 Omnia 构建包调用 Vercel Gateway；它不是自包含 TypeSafe 原生直连。真实 Jev 决策、真实主模型对白质量及长期对照尚未验证。
- 两条待实现路径的接口、CORS 预检和密钥边界见 [JEV_DIRECT_API_NOTES_2026-09-27.md](JEV_DIRECT_API_NOTES_2026-09-27.md)；成熟插件的源码对照与产品化建议见 [RESEARCH_ST_PLUGINS_2026-09-27.md](RESEARCH_ST_PLUGINS_2026-09-27.md)。OPTIONS 预检不是有效密钥 POST 成功的证据。

## 恢复开发时的顺序

1. 核对当时的 TypeSafe 原生 API、Gateway API、价格、配额与 CORS，并先给实验设定明确的调用预算和停止条件。
2. 将本机桥做成不依赖相邻仓库的 TypeSafe 服务端直连；用 mock 覆盖认证、限流、超时、畸形响应、取消与过期拒绝，再做小额真实 smoke。
3. 如仍有需求，单独评估浏览器 Gateway BYOK。默认只在会话内持钥，明确浏览器脚本可见的边界；验证真实 POST、重载、模式切换、脱敏诊断。
4. 再处理设置迁移、连接测试、非秘密配置导入导出、安装升级回归和有预算的角色质量对照。只有质量证据支持时才扩大功能。

Omnia 主线只吸收经过验证的候选/快照、权限边界与异步过期控制概念；ST 事件、世界书读取、注入与面板继续属于此适配器。主线不依赖 Jev 或本扩展。

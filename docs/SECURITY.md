# 安全与失败边界

- 原生 ST 扩展没有密钥字段，也不从扩展设置、角色卡或世界书读取密钥。`AI_GATEWAY_API_KEY` 只在 Node 桥进程的环境变量中。默认 mock 可完全离线运行。
- 桥只监听 `127.0.0.1`，只接受配置的 `ST_ALLOWED_ORIGIN`，限制请求体大小与字段长度，拒绝其他来源。Origin 检查主要防普通恶意网页，**不能防同机进程伪造请求**；因此它是实验用本机边界，不是公网服务。不要把桥端口映射到外网。
- 前端只允许 loopback HTTP `serviceUrl`。桥响应须经过结构与来源 ID 校验；未在当前候选集合的证据 ID 被拒绝。
- 超时、断线、非法响应、Jev 过载都使本轮回到原生 ST 生成。两次连续 429/overload 后冷却 30 秒；无自动重试风暴。停生成、换聊天或角色会取消在途请求并丢弃旧结果。
- DEBUG 诊断可能显示私密聊天和世界书内容，仅供本机实验，不自动保存快照；切换聊天或角色时清除旧诊断。设置存入 ST 的 `extensionSettings.omniaCognition`，不包含凭据。
- 世界书候选暂时通过关键词兼容检索，不能判定某条秘密是否为角色所知。这是实验的主要语义风险；用含隐秘事实的角色卡比较时需人工核查角色越界。
- 若此前已经在聊天或其他不受控位置公开过真实 API key，实际联网前应在服务商侧轮换。不要把旧值复制进本仓库。

# 原生 SillyTavern 扩展实施计划

目标：把 Phase 0 的认知核心包装成可直接安装的 ST UI 扩展，保留本机 Jev 桥，替换对 TavernHelper 全局脚本的运行依赖。

1. 宿主适配：使用 `SillyTavern.getContext()` 读取当前单人聊天、角色卡及绑定世界书；用 ST 事件源接入生成周期，用 `setExtensionPrompt` 注入，并在结束、停止、换聊天及卸载时清理。针对宿主映射和清理写测试。
2. 扩展包装：仓库根目录提供 `manifest.json`、构建生成的 `index.js`、`style.css`。ST 原生扩展抽屉持久保存非敏感设置，提供状态、调试详情和桥连接检查。没有 Jev 密钥输入框。
3. 桥改进：增加只读 `/health`，报告运行状态和密钥是否已配置，不返回密钥；保持 Origin 检查、loopback 监听和输入验证。
4. 发布与验收：构建文件纳入 Git；在隔离 ST 1.19.0 中以本地扩展目录安装，停用旧脚本，使用本机假模型分别验证 DEBUG 注入一次和 OFF 不注入。运行类型检查、测试、构建，并更新中文安装与限制文档。

范围边界：本轮不加入完整 Omnia 世界状态、角色认识论隔离、向量检索或真实 Jev 质量结论。ST 扩展管理器从 Git URL 安装要求公开可访问的远程仓库；本轮不发布远程，仅交付可复制的本地包及可用于以后仓库 URL 安装的根目录结构。
